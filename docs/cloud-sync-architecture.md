# 第 47 课：账号与云同步基础架构

## 目标

用户登录微信、QQ 或手机账号后，在多台设备之间共享计划、专注历史、成就和每日目标。

## 为什么必须增加后端

浏览器前端不能安全保存微信 AppSecret、QQ AppKey 或短信 SecretKey。这些密钥一旦写进
`script.js`，任何访问网页的人都能看到。因此第三方授权、短信发送、登录会话和数据库读写
必须由服务端完成。

## 分层

1. 前端界面：显示登录方式、同步状态和退出登录。
2. `sync-tools.js`：创建、校验同步快照，判断上传或下载。
3. `sync-api.js`：定义前端与后端通信的固定接口。
4. 后端：验证微信、QQ 回调及手机验证码，创建安全会话。
5. 数据库：保存用户、登录身份和每个用户的最新同步快照。

## API 契约

| 方法 | 地址 | 作用 |
| --- | --- | --- |
| GET | `/api/account` | 获取当前登录账号 |
| GET | `/api/auth/wechat/start` | 开始微信 OAuth 登录 |
| GET | `/api/auth/qq/start` | 开始 QQ OAuth 登录 |
| POST | `/api/auth/phone/code` | 发送手机验证码 |
| POST | `/api/auth/phone/verify` | 验证手机验证码并登录 |
| POST | `/api/auth/sign-out` | 退出当前账号 |
| GET | `/api/sync` | 下载账号的最新数据 |
| PUT | `/api/sync` | 上传当前设备的数据 |

登录成功后，后端应设置 `HttpOnly`、`Secure`、`SameSite=Lax` 的会话 Cookie。前端不保存
第三方 access token，也不把平台密钥放入 localStorage。

## 当前同步范围

- 计划及子任务
- 专注历史
- 已解锁成就
- 每日专注目标

主题、音量和正在运行的计时器属于设备偏好，暂不跨设备同步。

## 本地开发模式

运行 `npm.cmd run dev` 后，手机号验证码由本地服务生成并自动填入页面，方便学习完整登录
流程。用户、会话和同步快照保存在 `.data/focus-plan.db`，该目录不会提交到 Git。

这个开发验证码不等于真实短信。正式部署时必须关闭 `developmentCode` 响应，并在服务端调用
短信供应商发送验证码。微信和 QQ 登录入口在平台凭据配置完成前保持禁用。

## 自动同步与冲突

本地保存计划、专注记录、成就或每日目标后，前端会合并短时间内的连续修改并自动上传。页面
重新可见或网络恢复时会重新检查云端版本。

每次自动上传都携带上次读取到的云端更新时间。若其他设备已经先上传，服务端返回 `409`，
前端停止自动覆盖并提示用户选择“上传本机数据”或“下载云端数据”。手动选择前，两份数据都
不会被静默删除。

## 接入前需要准备

- 一个可公网访问的 HTTPS 域名
- 审核通过的微信开放平台网站应用及回调域
- 审核通过的 QQ 互联网站应用及回调地址
- 腾讯云短信应用、短信签名、验证码模板和 API 密钥
- PostgreSQL 数据库或等价的云数据库

真实值填写在服务端 `.env` 中；仓库只提交不含密钥的 `.env.example`。
