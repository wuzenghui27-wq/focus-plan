# 稍后提醒课程笔记

## 学习目标

这一课实现“提醒我稍后再处理”，并学习一个功能如何穿过前端的多个层次。

## 第一步：扩展数据结构

每个计划增加：

```js
snoozedUntil: null
```

没有推迟时是 `null`；选择稍后提醒后，它会保存一个 ISO 时间字符串，例如：

```js
snoozedUntil: "2026-07-29T08:15:00.000Z"
```

保存绝对时间比保存“剩余 15 分钟”更可靠。即使刷新网页，也可以重新计算是否到期。

## 第二步：编写纯规则

`reminder-tools.js` 负责：

- 只接受 5、15、60 分钟三个选项。
- 根据当前时间计算新的提醒时间。
- 验证从本地存储读取的时间。
- 判断计划应该使用原始提醒时间，还是推迟后的时间。

这些函数不操作页面，也不操作存储，所以可以直接用 Node.js 自动测试。

## 第三步：添加用户操作

`reminder-presenter.js` 在计划提醒中创建一个原生 `select` 菜单：

- 5 分钟后
- 15 分钟后
- 1 小时后

展示层通过 `onSnooze(reminder, minutes)` 把结果交给业务层，而不是自己修改计划。

## 第四步：更新并保存计划

`script.js` 中的 `snoozePlanReminder()`：

1. 使用 `planId` 找到计划。
2. 计算 `snoozedUntil`。
3. 将 `reminded` 改回 `false`，允许它再次提醒。
4. 调用 `savePlans()` 持久化。
5. 显示操作成功反馈。

## 第五步：避免重复提醒

提醒检查仍然以 `reminded` 作为开关：

- 成功显示提醒后设为 `true`。
- 用户选择稍后提醒时重新设为 `false`。
- 到达 `snoozedUntil` 后再次显示，并重新设为 `true`。

这形成了一个清楚的状态循环，而不是额外创建多个计时器。

## 当前边界

稍后提醒菜单属于网页前台的应用内提醒。后台系统通知由操作系统绘制；要直接在系统通知中增加
“稍后提醒”按钮，需要让 Service Worker 与持久化数据库通信，后续会和 Web Push 一起实现。
