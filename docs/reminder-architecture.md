# 提醒系统架构

## 两种展示通道

### 网页内提醒

页面处于前台时使用。应用可以完全控制它的布局和交互：

- 手机端：顶部安全区下方滑入，支持向上滑动或点击关闭。
- 电脑端：左下角滑入。
- 最多显示三条，相同 `tag` 的提醒自动去重。
- 使用“应用图标 + 应用名 + 时间 + 标题 + 正文”的信息层级。
- 点击提醒进入对应功能页；计划提醒会继续打开相应计划详情。

### 系统通知

页面进入后台时使用 `ServiceWorkerRegistration.showNotification()`。系统通知由操作系统渲染，
网页不能指定它在屏幕上的具体位置。通知会携带应用图标和目标页面，点击后聚焦已有页面并跳转，
或打开新的应用页面。

## 设计依据

当前交互参考了主流任务应用和手机操作系统的通知模式：

- 通知内容短而明确，先显示事件，再显示计划名称或完成结果。
- 同一计划使用稳定的 `tag`，避免短时间出现重复通知。
- 通知本身可以点击，并直接带用户进入产生提醒的内容。
- 计划提醒可推迟 5 分钟、15 分钟或 1 小时，推迟时间保存在计划数据中。
- 页面前台使用应用内提醒；页面后台交给操作系统显示，尊重用户的通知权限和系统专注模式。

## 代码分层

- `reminder-tools.js`：计算提醒时间，判断计划是否到期。
- `reminder-presenter.js`：网页提醒的位置、队列、动画和滑动关闭。
- `script.js`：选择网页内提醒或系统通知，并更新计划的提醒状态。
- `service-worker.js`：后台系统通知的点击行为。

## 稍后提醒的数据流

1. `reminder-presenter.js` 显示稍后提醒菜单，只负责收集用户选择。
2. `script.js` 根据提醒中的 `planId` 找到计划，写入 `snoozedUntil`，并把 `reminded` 恢复为 `false`。
3. `savePlans()` 将新时间保存到本地存储，并参与已有的账号同步。
4. `reminder-tools.js` 在后续检查中优先使用 `snoozedUntil`，到达时间后再次提醒。
5. 再次提醒成功后，`reminded` 变为 `true`，避免反复弹出。

## 后台调度的数据流

1. `savePlans()` 防抖触发后台提醒同步。
2. `push-reminder-tools.js` 过滤已完成或已提醒计划，并计算最终提醒时间。
3. API 按设备 endpoint 把任务写入 SQLite 的 `push_reminder_jobs`。
4. 服务器调度器每 15 秒读取到期任务并发送 Web Push。
5. 成功任务标记为 `sent`；临时失败指数退避；失效订阅连同任务一起删除。
6. 页面可见时，Service Worker 把消息交给应用内提醒；页面隐藏或关闭时显示系统通知。

相同 endpoint、planId 和提醒时间不会重复发送。编辑时间或选择稍后提醒会将任务重新设为
`pending`。

## 当前限制

本地 Node 服务必须持续运行。正式上线后，需要把同一套任务表和调度器部署到长期在线的服务器。
当前任务按设备 endpoint 保存，后续还应绑定登录账号，以便管理用户的多台设备。
